# 用户节点列表

登录后通过个人工作台「节点列表」进入 `/nodes`。此页面使用现有 Cookie 鉴权的 `GET /api/v1/client/bootstrap`，与管理员节点管理共用数据库，不维护第二份节点配置。浏览器仍走 Next.js 同源 API 代理。

## 展示和权限

只展示节点名称、地区、普通/专线类型和管理员设定的流量倍率。支持按名称/地区搜索、按线路类型筛选；倍率使用 `rate_permille / 1000`，保留最多三位小数。例如 500 为 0.5×，1250 为 1.25×，不根据线路类型硬编码价格。

列表只包括已启用、符合当前套餐及节点套餐白名单的节点。未登录会跳转登录；无套餐、尚未开始、到期、额度用尽或不允许的测试权益由后端拒绝，并隐藏节点。管理员浏览此用户页面也不能绕过订阅检查；管理员维护配置仍使用「节点管理」。空目录和搜索无匹配分别提示。

返回的每个节点仅包含 `id`、`name`、`region`、`line_type`、`rate_permille`、`version`。目录模式的元数据查询不读取 `ciphertext`；页面不调用管理员详情或原生客户端配置接口，不读取、下载或渲染 YAML、端口、服务器地址、密码等连接参数。节点名称与地区是管理员填写的公开文案，请勿把密钥写入这些字段。

## 同步配置

在 `frontend/.env` 中配置：

```dotenv
NODE_LIST_REFRESH_MS=30000
```

这是 Next.js 服务端在请求时读取的非敏感配置，仅刷新间隔传递给浏览器。允许 5000–300000 毫秒的整数；缺失或无效时回退 30000。修改后重启 Next.js 并重新加载页面，无需重新构建。无需新增后端环境变量或数据库迁移。

首次打开、手动点击「同步节点」、返回页面和网络恢复时刷新；页面可见期间按配置间隔轮询，隐藏时暂停轮询。并发触发合并为一个请求，离开页面/退出账户时取消未完成请求并清理监听器。管理员修改名称、类型、倍率、套餐权限，或停用/删除节点后，在下一次成功同步体现；这不是 WebSocket 瞬时推送。失败时收起旧列表并提供重试，避免把过时节点表示为当前可见。

「套餐可见」不表示实时在线、低延迟或已连接，页面不做模拟测速，不启动代理、不创建原生会话、不改计费流程。

## 验证

- `bash scripts/node.sh npm --prefix frontend run test:nodes`：配置边界、倍率精度和搜索/类型组合。
- `python3 scripts/test-native.py`：使用私有临时 PostgreSQL，包含 `TestWebNodeListPostgres` 的字段白名单、套餐过滤、管理员变更同步、到期/额度/登录拒绝回归。
- `bash scripts/node.sh python3 scripts/test-node-catalog.py --skip-build --output <新目录>`：构建后运行真实 Next.js/Gin/PostgreSQL/浏览器节点同步、搜索和手机布局，以及受控错误/空/失效状态、可见性轮询与并发请求测试；继续执行已有 Mihomo 流量验收。

新增测试接入现有根目录 CI。测试不读取或修改开发 `.env`、用户数据库或公网代理节点。
