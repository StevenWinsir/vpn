# 控制平面与代理数据平面

## 当前结构

浏览器 Next.js/Mantine → 当前前端来源 `/api/v1/*` → Next.js Node 动态代理 → Go/Gin API → PostgreSQL。业务、鉴权和购买判断全部在 Go 完成，Next.js 不访问数据库，也不保存代理密码。数据库独立 schema 减少与已有业务的碰撞。

Next.js 服务端运行时读取 `API_INTERNAL_URL`，默认 `http://127.0.0.1:8080/api/v1`；此地址不进入浏览器配置。浏览器固定使用同源相对路径，`/api/runtime-config` 仅提供该固定路径与超时。后端公网域名可通过独立的反向代理入口继续访问，不改变网站走同机回环的链路。两者的 Cookie 按各自访问域名保存，不会自动跨域共享。

代理仅覆盖 `/api/v1/*`，普通请求体上限与 Go 一致为 8192 字节，管理员节点 YAML 接口为 128 KiB；保留 Origin、Cookie、Authorization、Idempotency-Key 和独立 Set-Cookie，禁用缓存及上游重定向跟随，拒绝路径穿越。不替换可信来源、不绕过 Go 的 CSRF/CORS，不转发客户端自行提供的 Host/Forwarded 头。部署仍需正确填写后端的前端来源白名单，代理下的 IP 限流聚合问题见下文。

当前 `/client/bootstrap` 只是受限元数据接口，不是订阅 YAML 下载地址。由于没有部署代理节点，接口明确报告 `proxy_service_ready=false`，不能据此展示客户端“连接成功”。

## 为什么不能仅靠隐藏 YAML

本地设备必须以某种形式持有建立代理连接所需的信息。隐藏入口、打包混淆或在客户端解密，只是降低普通用户的直接可见性，不能对控制本机的用户保证配置不可提取。不要承诺绝对隐藏 server/port/password。

共享的 Shadowsocks 密码无法可靠绑定到单个网站用户。只让后端停止返回配置，也不能让已经缓存密码的客户端自动失去节点访问能力。用户提供的样例节点和共享密码未写入本项目。

## 已实现的开发闭环

管理员角色可以在 `/admin/nodes` 导入和编辑 YAML、地区、普通/专线类型、倍率、套餐权限与启用状态。密文、元数据、版本及审计在事务中保存，编辑详情使用一致的只读快照，过期版本写入会被拒绝。

原生客户端使用独立的不透明 Bearer 会话，服务端仅存令牌哈希，检查账号、套餐、设备数、配额、有效期与配置版本。macOS 可显式选择将密码保存在绑定 API 地址的非同步 Keychain 项中；每次进程重开仍须在线登录。原生会话不是网页 JWT/刷新 Cookie，也没有离线授权模式。

核心只取得当前选中节点的秘密，其他可选节点仅返回元数据。60 秒心跳/流量上报与 90 秒授权租约负责官方客户端停连；管理员保存不等于推送式瞬时撤销。切换节点或倍率先停连、结清旧批次，再绑定新配置。普通线路依然经过远端代理，不是本地 DIRECT 绕过。

**计费来源保留为客户端上报**：累计上传/下载、严格单调批次、幂等重试、行锁事务与整数倍率快照共同生成流量账本。流量回执不能擅自改变已绑定倍率或配置；异常回执保留待确认批次并停连。它们防止协议错误、重复扣费和部分重放，但不能证明受控终端没有伪造或省略用量。

真实浏览器、Gin/PostgreSQL 与 Mihomo 受控代理的验收入口是 `scripts/test-node-catalog.py`；原生应用验收是 `scripts/test-macos-managed.py`。详见 [节点与计费边界](admin-node-metering.md)。上述验收不是公网商业线路、全设备 TUN 或生产抗作弊证明。

## 尚未实现的节点强制执行与商业能力

节点仍需支持每用户/每设备可撤销凭据、短期授权、到期及配额拒绝、已建立连接中断和节点离线策略；这些访问控制可以与“仅客户端上报扣费”分离，不能假设任意共享 SS 服务都支持。没有独立可信用量证据时，恶意客户端少报/不报的商业风险仍须明确接受，不能靠加一个签名密钥消除。当前生产配置保护不会因为开发验收通过而解除。

真实支付仍需渠道选择、回调验签与幂等、金额/币种/商户核对、事务开通、退款和补单对账。浏览器支付成功跳转不能作为开通依据。测试订单始终保留测试来源，只能在明确启用的开发模式授权。

## 生产化尚缺的安全措施

当前 IP 限流存在单进程内存中；多副本需要共享限流与可信反向代理配置。当前未信任任何代理转发头，不要直接配置“信任全部代理”。

当前刷新令牌按数据库哈希原子轮换，网页标签页内合并刷新请求；尚未实现跨标签页协调、刷新令牌族的重放侦测与历史令牌撤销策略。正式原生协议应补全设备绑定、异常重复使用检测和密钥轮换方案。Cookie 部署应保持同站 HTTPS，跨站部署需重新设计 CSRF/SameSite 策略。

补齐邮箱验证、密码找回和密码修改后的会话撤销；管理员独立 RBAC/MFA；CSP/反向代理 TLS/HSTS；安全日志与可观察性；数据库最小权限、加密备份、恢复演练；版本化迁移和回滚；支付与流量账单对账；合规政策、用户协议、退款政策和开源许可审查。

当前提供注册/登录、测试购买、管理员节点目录和官方 macOS 客户端计费联调闭环，不宣称完成上述生产运营能力。
